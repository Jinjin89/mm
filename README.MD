# 🎵 音乐平台任务式开发文档（Self-Hosted）

## 一、总体目标
开发一个支持 **Web 网页端、Android、iOS 客户端** 的音乐平台。  
平台需支持 **用户管理、曲库上传与转码、流媒体播放（HLS）、搜索、推荐、订阅与权限控制**，并保证 **所有数据与服务本地化部署**。  

---

## 二、系统模块与任务分解

### 1. 基础设施

#### 任务 1.1：搭建开发环境
- **内容**：使用 Docker Compose 搭建 Postgres、Redis、MinIO、Django、Celery、Next.js、React Native Dev Server。
- **验收标准**：本地一键启动所有容器；API 与 Web 能访问。

#### 任务 1.2：生产环境部署
- **内容**：Kubernetes 或单机 Docker Swarm，Nginx 反向代理 + HTTPS。
- **验收标准**：所有服务可通过域名访问，API 有健康检查。

#### 任务 1.3：对象存储与 CDN
- **内容**：部署 MinIO 本地对象存储，内网直连，必要时结合 Nginx 提供切片分发。
- **验收标准**：上传音频文件 → API 返回可访问的签名 URL。

---

### 2. 后端服务（Django + DRF）

#### 任务 2.1：用户与权限系统
- **内容**：Postgres 存储用户，支持邮箱/手机号注册登录，基于 JWT；权限分级：普通用户、VIP、管理员。
- **验收标准**：可创建用户、登录、返回 JWT Token。

#### 任务 2.2：曲库管理
- **内容**：表结构设计（曲目、专辑、艺人、资产），上传音频触发 Celery → FFmpeg 转码 HLS → 存入 MinIO。
- **验收标准**：上传 1 首歌 → 自动生成 m3u8 文件，可播放。

#### 任务 2.3：播放与防盗链
- **内容**：API 返回签名 URL（短时有效），HLS 播放。
- **验收标准**：未登录用户请求被拒；登录用户可正常播放。

#### 任务 2.4：播放记录与统计
- **内容**：记录每次播放事件，存储用户、曲目、时间、进度。
- **验收标准**：能查询用户播放历史，生成热门榜单。

#### 任务 2.5：订阅与计费（本地模拟）
- **内容**：数据库保存订阅状态（Active/Expired），人工录入支付结果。
- **验收标准**：非订阅用户限制高码率/下载权限。

---

### 3. 前端（Web - Next.js）

#### 任务 3.1：用户界面
- **内容**：登录/注册、首页推荐、搜索、播放页面。
- **验收标准**：浏览器能播放音乐，展示歌词与封面。

#### 任务 3.2：播放器实现
- **内容**：使用 hls.js 实现 HLS 播放，支持播放/暂停/进度条/音量。
- **验收标准**：能连续播放、切换曲目不卡顿。

#### 任务 3.3：歌单与收藏
- **内容**：创建/编辑歌单，收藏曲目。
- **验收标准**：能添加到歌单并持久化。

---

### 4. 客户端（Android & iOS - React Native）

#### 任务 4.1：登录与导航框架
- **内容**：支持 JWT 登录，底部 Tab 导航（首页、搜索、歌单、我的）。
- **验收标准**：能登录并正常跳转。

#### 任务 4.2：移动播放器
- **内容**：使用 `react-native-video` 播放 HLS，支持后台播放、锁屏控制、耳机线控。
- **验收标准**：切到后台音乐不断，锁屏能暂停/播放。

#### 任务 4.3：离线缓存（加密）
- **内容**：曲目下载到本地加密存储，订阅过期后不可播放。
- **验收标准**：断网情况下仍可播放缓存曲目。

---

### 5. 搜索与推荐

#### 任务 5.1：搜索服务
- **内容**：Postgres 全文检索（后期扩展 Elasticsearch）。
- **验收标准**：输入关键词返回曲目/艺人。

#### 任务 5.2：推荐逻辑
- **内容**：热门榜单、相似标签推荐（初期基于规则）。
- **验收标准**：首页推荐展示最新/热门曲目。

---

### 6. 运营与合规

#### 任务 6.1：后台管理系统
- **内容**：管理员上传/下架歌曲，配置推荐位与 Banner。
- **验收标准**：管理员能设置首页 Banner 与推荐歌单。

#### 任务 6.2：版权与安全
- **内容**：曲库表存储版权有效期，到期自动下架；API 签名 URL 防盗链。
- **验收标准**：过期歌曲无法访问。

---

### 7. 运维与监控

#### 任务 7.1：日志与监控
- **内容**：ELK/Prometheus，采集 API QPS、播放成功率。
- **验收标准**：Grafana 展示播放次数与错误率。

#### 任务 7.2：错误追踪
- **内容**：集成 Sentry，收集前后端错误。
- **验收标准**：人为制造 500 错误 → Sentry 报警。

---

## 三、开发里程碑

- **M1（2 周）**：环境搭建 + 用户体系 + 上传/转码/播放闭环（Web Demo）。  
- **M2（4 周）**：Web MVP（搜索、歌单、排行榜）+ 移动端播放器（前台播放）。  
- **M3（4 周）**：移动端增强（后台播放、离线缓存）+ 后台管理系统。  
- **M4（4–6 周）**：推荐系统 + 权限控制 + 运维监控 → 内测版本。  
- **M5（上线）**：订阅管理、版权合规、安全防护 → 正式发布。  

---

## 四、优先级标记

- 🔴 **高优先级**：M1 + M2 基础功能（闭环跑通必须）。  
- 🟡 **中优先级**：M3、M4（增强体验，进入内测）。  
- 🟢 **低优先级**：M5 及后续演进（长期优化）。
